## 探针 A — 限额读取通道

### Claude Code

**statusline 通道（文档原方案）**：用 `--settings` 挂一个把 stdin 原样落盘的脚本，pty 驱动一次交互式会话。结果：

- 第 1 次调用（首个响应之前）：**没有** `rate_limits` 键。
- 第 2 次调用（首个响应之后）：

```json
"rate_limits": {
  "five_hour": {"used_percentage": 14.0, "resets_at": 1788370200},
  "seven_day": {"used_percentage": 3,    "resets_at": 1788552000}
}
```

- 完整键列表：context_window, cost, cwd, exceeds_200k_tokens, fast_mode, model, output_style, prompt_cache, prompt_id, rate_limits, scratchpad_dir, session_id, session_name, thinking, transcript_path, version, workspace。
- 官方文档（code.claude.com/docs/en/statusline）另列了 `spend_limit` 桶（2.1.251+，apps gateway 场景），本机未出现。
- **`-p` 模式下 statusline 不触发**（挂了同样的 settings 跑 `-p`，没有 dump）。所以守护进程不能靠它。

**stream-json 通道（更适合守护进程）**：`claude -p --output-format stream-json --verbose` 每次运行都会吐一条：

```json
{"type":"rate_limit_event","rate_limit_info":{
  "status":"allowed",
  "resetsAt":1788370200,
  "rateLimitType":"five_hour",
  "overageStatus":"rejected","overageDisabledReason":"org_level_disabled","isUsingOverage":false,
  "unifiedWindows":{
    "five_hour":{"utilization":0.13,"resetsAt":1788370200},
    "seven_day":{"utilization":0.03,"resetsAt":1788552000}}},
 "session_id":"..."}
```

- 官方 SDK 类型：`status` ∈ allowed / allowed_warning / rejected；`rateLimitType` ∈ five_hour / seven_day / seven_day_opus / seven_day_sonnet / overage。`unifiedWindows` 未见文档，属于当前版本实际输出。
- `rateLimitType` 就是文档想要的「绑定窗口」。

**桶清单（本机 Team 账号）**：`five_hour`、`seven_day`。按模型分的周桶（opus/sonnet）在类型定义里存在，本机未出现，数据模型要允许出现。

**没有按需查询**：没有 `claude usage` 子命令，`/usage` 只是 TUI 命令。要「现在读一次」只能发一个最小 haiku 调用（实测单次约 $0.013 估算成本，也占额度）。**建议**：v0.1 的 Claude 侧显示「最近一次采样」，采样来源为守护进程自己的每次运行 + 可选地让用户交互会话的 statusline 脚本也往 SQLite 写一份（被动采集）。

### Codex

**不需要碰内部 HTTP 端点。** `codex app-server`（stdio 上的 JSON-RPC）提供 `account/rateLimits/read`，用本地登录态直接返回，不占额度。握手：

```
→ {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"clientInfo":{"name":"keji","version":"0.0.1"}}}
→ {"jsonrpc":"2.0","method":"initialized"}
→ {"jsonrpc":"2.0","id":2,"method":"account/rateLimits/read"}
```

实测返回（已删节）：

```json
{"rateLimits":{
   "limitId":"codex",
   "primary":  {"usedPercent":100,"windowDurationMins":300,  "resetsAt":1788361284},
   "secondary":{"usedPercent":47, "windowDurationMins":10080,"resetsAt":1788892271},
   "planType":"plus","rateLimitReachedType":"rate_limit_reached",
   "credits":{"hasCredits":false,"unlimited":false,"balance":"0"}},
 "rateLimitsByLimitId":{
   "codex":{...同上...},
   "base_model_inference":{"limitName":"gpt-reserve",
      "primary":{"usedPercent":6,"windowDurationMins":10080,"resetsAt":1788936876},"secondary":null}},
 "rateLimitResetCredits":{"availableCount":0,"credits":[]}}
```

- 另有通知 `account/rateLimits/updated`（稀疏增量），以及 `account/read`（返回 planType / email）。
- **桶清单**：`codex` 下 primary（5h）+ secondary（周），`base_model_inference` 只有周桶。`rateLimitsByLimitId` 是按 limit_id 的字典，服务端下发，桶会变。
- **文档里说的「独立的 code review 周限额」未在本账号出现**，协议 schema 里也没有 code_review 相关定义。可能是别的套餐才有、或用过 `codex review` 后才出现。数据模型按「可变桶集合」设计即可覆盖。
- 注意：`codex app-server` 启动后会附带拉模型列表、起 remote-control websocket 等，日志噪音大，`RUST_LOG` 不要开 info。

## 探针 B — 阻塞信号

### Codex（实测，5h 窗口 100%）

`codex exec --json -s read-only -C <dir> '...'`：

- 退出码：**1**
- stdout JSONL：

```
{"type":"thread.started","thread_id":"01a06248-458d-7432-91f9-4406d4d3a97e"}
{"type":"turn.started"}
{"type":"error","message":"You've hit your usage limit. Upgrade to Pro (...), visit https://chatgpt.com/codex/settings/usage to purchase more credits or try again at 7:01 PM."}
{"type":"turn.failed","error":{"message":"...同上..."}}
```

- 重置时间只有本地时间文本「7:01 PM」，没有日期、没有 epoch。**不要解析这句话**，阻塞后直接调 `account/rateLimits/read` 取 `resetsAt`（实测两者一致：1788361284 = 19:01 本地）。
- 即使被拦，`thread_id` 也已产生，可以记进 `run`。

## 探针 C — 无头执行与续接

### Claude Code（实测通过）

```
claude -p --model haiku --output-format json 'Remember the secret word is PLUM. Reply with exactly: ACK'
  → exit 0, result "ACK", session_id 16733d4b-...
claude -p --model haiku --output-format json --resume 16733d4b-... 'What was the secret word? Reply with only the word.'
  → exit 0, result "PLUM", session_id 不变
```

- 结果 JSON 关键字段：session_id, is_error, subtype, result, total_cost_usd, num_turns, duration_ms, api_error_status, terminal_reason, usage, modelUsage。
- 还有 `--session-id <uuid>` 可以**预先指定** id。建议守护进程用它：运行开始前就把 id 写进 `run`，进程中途被杀也能续接。
- 全新目录下 `-p` 没有弹信任确认，per-task worktree 方案可行（交互式才会弹）。
- 从另一个 Claude Code 会话里嵌套启动需要清掉 `CLAUDE*` 环境变量；launchd 下不存在这个问题。
- stdin 不重定向会等 3 秒并打警告，守护进程用 `< /dev/null`。

### Codex（部分）

- `codex exec --json` 第一条事件 `thread.started` 给出 `thread_id`，被限流时也有。
- `codex exec resume <SESSION_ID> [PROMPT]` 存在，另有 `fork`、`--last`、`-o/--output-last-message <FILE>`、`--output-schema`。
- **实际续接未跑**（窗口 19:01 才重置）。补测命令：

```
codex exec --json -s read-only -C <dir> 'Remember the secret word is PLUM. Reply with exactly: ACK'
codex exec resume <thread_id> 'What was the secret word? Reply with only the word.'
```

## 对 MVP 文档的具体修订建议

1. **v0.1 `keji status`**：Codex 侧是实时读取；Claude 侧是「最近采样 + 采样时间」，并注明来源（run / statusline）。文档里「Claude 侧如果 representative-claim 有值」改为「以 `rate_limit_info.rateLimitType` 指向的窗口为准」。
2. **`sample` 表**：官方给的是 used 而不是 remaining（Claude 用 0–100 的 `used_percentage`，stream-json 里是 0–1 的 `utilization`；Codex 是整数 `usedPercent`），字段名建议直接存 `used_pct` 并统一到 0–100；再加 `window_mins`（Codex 给了，Claude 由桶名推）。
3. **`bucket.bucket_key`**：Codex 要带 limit_id，建议 `codex:<limit_id>:primary|secondary`，如 `codex:codex:primary`、`codex:base_model_inference:primary`；Claude 用 `claude:five_hour`、`claude:seven_day`，并允许 `seven_day_opus` 等新桶自动入库。
4. **第 3 节「两边都有可读的限额通道」**：Claude 侧要加限定：只在产生响应时可读。这不影响「不做手动打卡」的结论，因为守护进程每跑一次任务就有一份新样本。
5. **探针 B 的 Codex 结论**：重置时间**不从报错文本取**，从 `account/rateLimits/read` 取。
6. **安全约束一节**可补两条具体开关：Codex 用 `-s workspace-write` + `-C` + `--add-dir`；Claude 用 `--permission-mode` 与允许工具清单。这两个开关本次只看了 help，未验证行为。

## 探针 D — 零付费核验（2026-09-23 实测）

本机 macOS，Claude Code 2.1.280，codex-cli 0.155.1。运行 `keji/billing.py` 的真实核验（只读登录状态，不启动模型）：

```
{"provider": "claude", "verified": true, "reason": "", "auth_method": "claude.ai/team", "verified_at": "2026-09-23T00:09:37+0400"}
{"provider": "codex", "verified": true, "reason": "", "auth_method": "chatgpt", "verified_at": "2026-09-23T00:09:38+0400"}
```

依据的原始输出：`claude auth status` 返回 `loggedIn=true, authMethod=claude.ai, apiProvider=firstParty, subscriptionType=team`；
`codex login status` 返回 `Logged in using ChatGPT`，`~/.codex/auth.json` 的 `auth_mode=chatgpt`、`OPENAI_API_KEY=null`。
环境中没有 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` 等变量，`~/.claude/settings.json` 无 `apiKeyHelper`、无 `env`。

`keji agent doctor` 输出：

```
claude: /opt/homebrew/bin/claude
  零付费核验: 通过（claude.ai/team，2026-09-23 00:09:38）
codex: /opt/homebrew/bin/codex
  零付费核验: 通过（chatgpt，2026-09-23 00:09:38）
```

结论：在这台机器的当前登录状态下，两个 adapter 的 `can_enforce_zero_spend` 为 true，派发门禁放行；
换一台机器或退出登录、导出 API key 后，门禁会在下一次 spawn 前重新核验并关闭。
