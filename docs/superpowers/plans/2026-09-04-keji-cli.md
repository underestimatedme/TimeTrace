# keji CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `keji` CLI (v0.1 status dashboard, v0.2 task queue with block/resume daemon, v0.3 on_success hooks) as a zero-dependency Python 3.9 package under `cli/keji/`.

**Architecture:** `db.py` owns all SQL over a SQLite file in `~/.keji/`. Two `ToolAdapter` implementations (Claude Code, Codex) expose the same `read_limits / start / resume` interface and return `RunResult`. `scheduler.run_once()` is a pure-ish function over `(db, adapters, config, now)` that implements one loop iteration of the state machine; `cli.py` wires argparse to it. Hooks write declarative task JSON to an inbox that the scheduler ingests.

**Tech Stack:** Python 3.9 standard library only (`argparse`, `sqlite3`, `subprocess`, `json`, `uuid`, `unittest`).

**Spec:** `docs/superpowers/specs/2026-09-04-keji-cli-design.md`

## Global Constraints

- Python 3.9 compatible syntax (no `match`, no `X | Y` type unions, use `typing.Optional`).
- No third-party imports anywhere in `cli/keji/` or `cli/tests/`.
- All timestamps are integer Unix epoch seconds.
- Only `db.py` contains SQL.
- Data directory is `~/.keji/`, overridable by env `KEJI_HOME` (tests use a temp dir).
- Task states: `pending`, `runnable`, `running`, `blocked`, `done`, `failed`.
- Bucket keys: `claude:<rateLimitType>` and `codex:<limit_id>:primary|secondary`.
- Tests run with `cd cli && python3 -m unittest discover -s tests -v`.

### Task 5: worktree + scheduler state machine

**Files:**
- Create: `cli/keji/worktree.py`, `cli/keji/scheduler.py`, `cli/tests/test_scheduler.py`, `cli/tests/test_worktree.py`

**Interfaces:**
- `worktree.ensure(repo: str, task_id: int, home: Path) -> tuple[path, branch]` runs `git worktree add -b keji/<id> <home>/worktrees/<id> HEAD` if missing and sets every remote's `pushurl` to `no_push://blocked`.
- `scheduler.run_once(db, adapters: dict[str, ToolAdapter], cfg, home, now=None, log=print) -> str` returns a short summary of what happened (`"idle"`, `"ran task 3 → done"`, `"circuit open"`, ...). Steps 1–11 of spec §6. Hook step calls `hooks.run_hook(...)` (Task 6) via an injectable `hook_runner` argument defaulting to the real one.
- `scheduler.pick_tool(task, rows, cfg, db, now) -> Optional[str]` implements spec §6 step 6 and writes `tool_switched` event.

- [ ] `test_worktree.py`: init a temp git repo with a commit and a fake remote, call `ensure`, assert worktree dir exists on branch `keji/1` and `git config remote.origin.pushurl` == `no_push://blocked`; second call is idempotent.
- [ ] `test_scheduler.py` with a `FakeAdapter(results: list[RunResult])`: (a) runnable task → done + `task_done` event + run row; (b) failed result → failed + last_error; (c) blocked result → blocked with `blocked_until >= reset_at`, then advancing `now` past it → runnable → next run uses `resume` with the same session_id; (d) `any_tool` task whose tool is exhausted switches tool and writes `tool_switched`; (e) task with session_id and exhausted tool is NOT switched; (f) circuit breaker: 3 failed runs → summary `circuit open`, nothing dispatched; (g) dependency: child pending until parent done, child failed when parent failed; (h) both tools exhausted → idle.
- [ ] Implement. Worktree creation is injected (`ensure_worktree` callable) so scheduler tests use a temp dir. Run. Commit `feat(keji): scheduler state machine and worktree isolation`.

### Task 6: hooks (v0.3), CLI commands, render, launchd, README

**Files:**
- Create: `cli/keji/hooks.py`, `cli/keji/render.py`, `cli/keji/cli.py`, `cli/launchd/com.keji.run.plist`, `cli/README.md`, `cli/tests/test_hooks.py`, `cli/tests/test_cli.py`

**Interfaces:**
- `hooks.extract_tasks(text: str) -> list[dict]` finds the first JSON array in model output; raises `ValueError` if none.
- `hooks.validate(items, max_tasks) -> list[dict]` normalises `{prompt, tool, any_tool}`.
- `hooks.run_hook(db, adapter, task, run_dir, home, cfg, now) -> Optional[Path]` resumes the session with `task.on_success + OUTPUT_CONTRACT`, writes `<home>/inbox/<task_id>-<now>.json`, event `hook_generated`; skips with `hook_rejected` when `task.generation >= 1`.
- `hooks.ingest(db, home, cfg, now) -> int` reads inbox files, validates, adds tasks with `generation = parent.generation+1`, `depends_on = parent_id`, `repo = parent.repo`; moves files to `inbox/done` or `inbox/rejected`.
- `render.status_table(rows, binding, now) -> str`, `render.tasks_table(tasks) -> str`, `render.events_table(events) -> str`.
- `cli.main(argv=None) -> int` with subcommands status/add/ls/run/logs/retry/rm/events per spec §3. `status` calls Codex `read_limits()` live first (errors → `sample_failure` event, still prints last samples).

- [ ] `test_cli.py`: with `KEJI_HOME` temp, `add` then `ls` shows the task; `add --repo` outside `allowed_repos` exits non-zero; `add --after 99` (missing) exits non-zero.
