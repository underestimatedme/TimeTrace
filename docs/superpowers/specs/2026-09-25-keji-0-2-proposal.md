## 1. 二维码配对 + 多机绑定

**现状**：电脑打印 8 位码，手机手动输入；一台电脑一次配对。服务端已支持一个账号多台 Runner，手机「你的 AI」和「设备与授权」已按列表展示。

**建议**
- 电脑端 `keji cloud login` 在终端里同时打印 8 位码和一个终端二维码（Unicode 半块字符，零依赖）。二维码内容 `keji://pair?code=XXXXXXXX&v=1`，不含任何凭据；码本身 10 分钟过期、一次性。
- 手机「绑定新电脑」卡片加「扫码绑定」按钮（AVFoundation 扫码，不引第三方库），扫到后走现有的检查 → 确认流程。注册 `keji://` URL Scheme，系统相机扫码也能直接拉起 App。
- 多机：保持现有模型，每台电脑一行；新增「重命名电脑」（默认用主机名），派发面板按名称选择。

**待你决定**：二维码里是否要带「电脑名 + 平台」用于扫码后预览（便于在多台电脑时确认扫的是哪台）？我建议带，信息与现在检查页展示的一致。

## 2. 电脑端开源（`cli/`）

**目标**：代码公开后仍然安全，且对陌生用户有用。

**建议分三块**
1. **安全审计与加固**（开源前必须做）：
   - 用独立审查跑一遍 `security-review` 与威胁建模：凭据读取（钥匙串、`~/.codex/auth.json`、`~/.claude/.credentials.json`）、子进程环境清洗、worktree 隔离、`--add-dir` 放行范围、Valley 通信、日志与输出尾巴是否可能带出代码中的密钥。
   - 输出尾巴上传前做密钥脱敏（常见 token 形态、`.env` 行、私钥块），并提供 `keji config set upload_output_tail false` 关闭。
   - 固定依赖面：维持纯标准库；加 `SECURITY.md`、漏洞报告渠道、签名发布（GitHub Release + SHA256）。
2. **拆仓与许可**：把 `cli/` 拆到独立公开仓库（例如 `keji-runner`），许可证建议 Apache-2.0（含专利授权）；Valley 接入地址做成配置项，文档里写清「默认连刻迹云」。
3. **让它对陌生人有用**：`brew install` 或 `pipx install` 一行安装、`keji setup` 交互向导（检测工具、登录状态、选择仓库、配对二维码、安装常驻）、`keji agent doctor` 已有的实时额度对照、README 的截图与隐私说明。

**待你决定**：许可证（Apache-2.0 / MIT / AGPL）；是否允许第三方自建 Valley（影响协议是否要公开文档化）。

## 3. 任务创建与关联

**问题**：一条一条手动建任务太重；任务之间没有关系；AI 任务的上下文（Claude / Codex 会话）不可见。

**建议**
- **默认 AI 执行**：新建任务默认执行者 = AI，默认工具 = 上次用的工具，默认电脑 = 唯一在线的那台；「我来做」降为次要选项。
- **一句话派发**：首页顶部一个输入框「让 AI 做点什么…」，输入一句话 + 选仓库，直接创建任务并派发；任务标题由第一行生成，项目自动归到该仓库对应的项目（仓库 = 项目，自动创建）。
- **批量 / 拆分**：派发前可以选择「让 AI 先拆成子任务」，AI 在电脑上读仓库后回传一个 Plan 列表，手机上勾选后批量派发（复用现有 Plan / 依赖模型）。
- **任务关联**：
  - 会话关联：Runner 已经记录 provider session id（断点续跑用）。把它回传并显示为「会话」，同一会话的后续指令可以「接着这个会话继续」。
  - 显式关联：任务详情里「追加指令」= 在同一 worktree、同一会话里继续；「基于此任务新建」= 新任务继承仓库与分支。
  - 结果关联：同一仓库的任务按分支串起来，任务详情显示「产出分支 keji/xxx，N 个提交，可一键合并」。

**待你决定**：「仓库 = 项目」是否可以作为默认（现有的手动项目 / 目标保留但不再是入口）？

## 4. 首页报告

**问题**：现在的日报是评分 + 时间分解，你看不出它能帮你做什么。

**建议**：报告回答三个问题，其余删掉。
1. **AI 替我干了什么**：今天完成 / 待验收 / 失败的任务，每条一句结果摘要和产出分支；「待验收」直接可点进去验收。
2. **我的订阅用得值不值**：每个工具今天用了多少额度、离重置还有多久、有没有「额度快重置但还剩很多没用」的浪费提示（例如 Codex 周额度剩 60%，3 小时后重置 → 建议现在派一批任务）。
3. **明天可以交给 AI 的**：未完成的任务 + 下一次额度重置时间，一键「安排在重置后执行」（复用定时派发）。

评分、效率指数、「时间杠杆」这类没有决策价值的数字全部下线。

**待你决定**：同意把报告改成「AI 产出 + 额度利用 + 明日安排」三段吗？

## 5. 使用习惯记录

**建议**：自建极简事件表，不接第三方统计 SDK（与隐私清单「不做追踪」一致）。
- 客户端上报结构化事件：`screen_view`、`dispatch_started/succeeded/failed`、`pairing_step`、`schedule_created`、`accept_plan`、`report_opened` 等，字段只含枚举与耗时，不含任务文字、仓库路径、账号。
- Valley 新增 `POST /events`（批量、离线缓冲、每人每日上限），落表按 30 天保留；后台出漏斗：配对完成率、首次派发耗时、派发成功率、报告打开率。
- 「数据与隐私」页加开关，默认开启并说明收集了什么。

**待你决定**：默认开启还是默认关闭？（App Store 隐私问卷需要同步改为「收集使用数据，不关联身份 / 或关联用户」。）

## 8. BetterOPC 重置信号 → 历史日历

**调研结论（2026-09-25）**
- BetterOPC 的 `robots.txt` 禁止 `/api/`，而重置历史日历正是页面加载后从 `/api/` 拉取；使用条款写明「自动化访问应遵守相应接入说明和额度限制」「索引或引用不等于授予转载、商用或再分发许可」。
- 站点有需要登录的「接入」页（`/integrations`），应是官方接入凭证。

**建议**：只走官方接入，不抓取页面。
- 你在 BetterOPC 登录后到「接入」页申请凭证，交给我放进 Valley 的密钥（不进仓库）。
- Valley 每天定时拉一次各产品（Codex / Claude Code / 以及它支持的其它产品）的重置事件，入库去重并永久保留历史；`GET /reset-signals?from=&to=` 返回区间事件。
- 手机「公共重置信号」改为月历视图：每天格子里按产品显示图标（Codex / Claude / Cursor…），点开看公告原文链接与时间。公共信号仍不改变个人额度判定。

**待你决定 / 需要你做**：去 BetterOPC「接入」页拿凭证；如果它的接入条款不允许商用或再分发，这一项改为只显示「最近一次重置」+ 链接。

- **右滑返回**：所有子页面恢复左边缘右滑返回。
- **今日 AI 为 0**：远程任务结束后服务端记录 AI 活跃时间段，今日 AI 与报告都能统计到。今日人工仍只统计你手动开的专注计时；AI 默认执行的用法下它为 0 是真实的，0.2 的报告会改为展示「待你验收」而非人工时长。

- **删掉无用设置**：「默认专注时长」「每周时间目标」「工作时间设置」没有任何功能读取，已从我的页移除（数据字段保留以兼容同步）。

- **解绑设备**：手机「设备与授权」可解绑；服务端吊销并取消等待中的任务；电脑端收到后清除凭据并等待重新配对；`keji cloud logout` 也会同步到服务端。
- **同步健壮性**：手机端所有服务端写入的枚举（任务状态、时间段类型 / 来源 / 置信度、执行状态）遇到未知值都回落，不再整份同步失败。
